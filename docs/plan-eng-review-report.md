## Architecture overview

```
[Client Browser]
        ↓ (HTTPS)
[Next.js App Router]  (Vercel Edge/Node)
  ├── /board/[id]       → Excalidraw editor (client-side)
  ├── /share/[id]      → Read-only view (client-side)
  ├── /api/boards       → REST API (Prisma)
  ├── /api/auth/[...]   → NextAuth v4 (JWT session)
  └── /api/excalidraw-worker → Static blob (worker bundle)
        ↓
[PostgreSQL]  (Prisma ORM)
```

**Key decisions:**
1. **Next.js App Router** — leverages RSC + client components
2. **Prisma + Postgres** — type-safe ORM, easy migrations
3. **NextAuth v4** — JWT sessions (no database session store)
4. **Excalidraw (client-side only)** — no server-side rendering of canvas
5. **Vercel deployment** — auto-deploy on push to `main`

## Findings

### 🔴 High priority (architectural)

#### ENG1 — No caching layer for API routes
**Files:** `src/app/api/boards/route.ts`, `src/app/api/boards/[id]/route.ts`
**Issue:** Every GET request hits Postgres directly. For 100+ concurrent users, this will be slow.
**Recommendation:** Add Redis (Vercel KV) or `Cache-Control` headers for read-heavy endpoints.
**Impact:** High — affects all board list/detail views.

#### ENG2 — No test framework
**Files:** Entire project
**Issue:** Zero unit tests, zero E2E tests. Refactoring is risky.
**Recommendation:** Add Jest + React Testing Library (unit), Playwright (E2E).
**Impact:** High — blocks confident refactoring.

#### ENG3 — No rate limiting on API routes
**Files:** `src/app/api/boards/route.ts`
**Issue:** API routes have no rate limiting. DoS possible.
**Recommendation:** Add `next-rate-limit` or Vercel Edge Middleware with rate limit.
**Impact:** Medium — only relevant for public-facing apps.

### 🟡 Medium priority (design)

#### ENG4 — `genId()` uses `Math.random()` (not crypto-secure)
**File:** `src/lib/boards.ts:3-8`
**Issue:** `Math.random()` is not cryptographically secure. For public board IDs, this is acceptable. But for user IDs, should use `crypto.randomUUID()`.
**Recommendation:** Replace with `crypto.randomUUID()` (Node 19+).
**Impact:** Low — board IDs are not security-critical.

#### ENG5 — No pagination on `GET /api/boards`
**File:** `src/app/api/boards/route.ts`
**Issue:** Returns ALL boards for user. For 100+ boards, response is large.
**Recommendation:** Add `?limit=20&offset=0` pagination.
**Impact:** Medium — only relevant when user has many boards.

#### ENG6 — No error monitoring
**Files:** `src/app/error.tsx`, `src/components/ExcalidrawEditorWrapper.tsx`
**Issue:** `console.error` is used for error logging. No Sentry/LogRocket integration.
**Recommendation:** Add Sentry for error tracking + performance monitoring.
**Impact:** Medium — hard to debug production issues without it.

### 🟢 Low priority (nice to have)

**Files:** `src/app/api/*`

#### ENG9 — `resolveUserId()` creates users auto-magically
**File:** `src/lib/boards.ts:22-48`

**Impact:** Low — only relevant for apps with user management.
